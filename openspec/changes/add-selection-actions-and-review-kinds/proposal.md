## Why

md-reviewer（npm 套件 `claudecode-md-reviewer`）是一個在本機執行的 Markdown 審閱器：在瀏覽器裡選取文章文字、寫下意見，意見存在文件旁邊的 `<檔名>.review.json`（以下稱「註解檔」），再交給 Claude 讀回去依意見修改。使用者實際用過之後提出兩個要求。

**第一，選取文字之後，想先決定要做什麼。** 使用者的原話：

> 「選取加註的功能調整一下。選取後，改成出現『複製』、『加註』二個按鈕。」

關於 [複製]，使用者補充：

> 「只複製選取的文字」

現在只要在文章裡選取文字，畫面就立刻跳出完整的加註框，游標也被移進意見輸入框。可是審閱時選字常常只是想複製一段話，例如貼進對話裡問 Claude，這時加註框反而擋路，還得多按一次「取消」。檢查程式時另外發現兩個相關的問題：加註框開著時又選了別的文字，加註框會直接換成新的引文、清空打到一半的意見，沒有任何提示；加註框開著時從左側清單換開另一份文件，加註框不會關，這時按下存檔，舊文件的引文就會被記到新文件上。

**第二，螢光筆的顏色沒有意義。** 使用者問：

> 「對了，四種螢光筆顏色有各自的意義嗎」

答案是沒有。加註框可以選黃、綠、粉紅、藍四種顏色，但程式、README、規格都沒有定義顏色代表什麼，「📋 複製給 Claude」產生的文字也不帶顏色，所以 Claude 只能把每一則都當成「照意見修改」。使用者接著要求：

> 「請你重新規劃，不必被侷限在四種顏色。看一般審閱應該有哪幾種出路，就找幾種顏色。要保留一種顏色是『見說明』（用語你再順）」

經過討論，使用者定案了八種分類，每一類都對應 Claude 收到後的一種處理方式（見下方 What Changes）。

## What Changes

### 選取後先出現小工具列（新功能）

在文章段落裡用滑鼠選取文字之後，不再直接跳出加註框，而是在選取處旁邊出現一個只有兩顆按鈕的小工具列：

- **[複製]**：只把選取的文字以純文字放進剪貼簿。成功時按鈕顯示「✓ 已複製」約 0.8 秒再恢復原狀，工具列留著，方便接著按 [加註]。瀏覽器拒絕剪貼簿寫入時，改用瀏覽器內建的複製指令（同樣只放純文字）；兩者都失敗時，按鈕改成「請按 Ctrl+C」，選取保留著讓使用者自己複製。
- **[加註]**：打開加註框。加註框的位置在按下 [加註] 的當下依選取範圍重新計算，上下左右都不會超出視窗。

工具列在以下情況收起：點別處、按 Esc、選取被取消或改變、開啟或重新載入文件、打開流程圖的放大檢視、視窗大小改變。

鍵盤操作：工具列出現時，焦點留在原處，不會自動跳到工具列上。這是為了不干擾三件事：按空白鍵捲動頁面、按 Shift＋方向鍵微調選取、選完直接打字。要用鍵盤操作時，按 Tab 進入工具列，在工具列裡用左右方向鍵切換按鈕、Enter 執行，再按 Tab 離開，按 Esc 收起。複製成功或失敗的結果，會透過一個螢幕閱讀器會朗讀的區域告訴使用者。

加註框開著時，再選取文字不會出現工具列，也不會蓋掉正在寫的意見。換開別的文件時，加註框一律先關閉，草稿不會寫進新文件。

### 八種註解分類取代四種顏色（新功能）

| 中文名 | 英文名 | 存檔的 `kind` 值 | 意思 | Claude 收到後怎麼做 |
|---|---|---|---|---|
| 見說明（預設） | See comment | `see-comment` | 以意見文字為準 | 照意見處理 |
| 同意 | Agree | `agree` | 認同這段 | 不改，也不算待辦 |
| 請展開解釋 | Explain more | `explain-more` | 太簡略、看不懂 | 在文件裡把這段補寫清楚 |
| 提出不同的方式供選擇 | Offer alternatives | `offer-alternatives` | 不要直接定案 | 列出 2～3 個做法與取捨讓使用者選，選之前不改文件 |
| 刪除這些字 | Delete this text | `delete-text` | 選取的文字刪掉 | 刪掉選取的文字，前後句調通順 |
| 第一性原理重新評估 | Rethink from first principles | `rethink-first-principles` | 做法的前提可能錯了 | 回到問題本身重新推導，回報結論，必要時改寫設計 |
| 不反向列舉 | State it positively | `state-positively` | 這段用「不做 X、不做 Y」列反面 | 改成正面描述要做什麼 |
| 此功能取消 | Drop this feature | `drop-feature` | 這個功能不做了 | 從文件拿掉這個功能，連帶的段落一起刪 |

英文名一律是祈使句形式的動詞片語（對修改者下的指示）；`kind` 值取英文名的小寫、以連字號相連，較長的去掉 this、it 這類代名詞。每一類的顏色、符號與完整處理文字寫在 design.md。具體改變如下：

- 加註框的四個顏色圓點換成八個分類選項，排成兩欄四列，「見說明」在第一格並標示「預設」。每次打開加註框都預設選「見說明」，所以不想分類的人操作跟現在一樣。
- 只有「見說明」必須寫意見；其他七類的名稱本身就是完整指示，意見可以留空。
- 註解檔裡每則新註解多一個 `kind` 欄位，不再寫 `color`。`comment` 一律存成字串，留空時存 `""`，不會省略這個欄位。
- 文章裡的螢光，開頭會有一個小色章，裡面是該分類的符號（例如「同意」是 ✓）。這是不靠顏色的辨識方式，色弱的使用者也分得出八類。右側卡片與滑鼠提示也都寫出分類名稱。
- **建立後可以改分類**：卡片上有一個小選單，只改分類，不改意見。
- **舊註解**：0.7.0 以前建立的註解只有 `color`、沒有 `kind`，一律當「見說明」處理，並且用「見說明」的顏色與符號顯示，不再沿用原本的顏色。程式不改寫舊檔，也不會替舊註解補上 `kind`。
- **「同意」不算待辦**：不計入左側清單的未解決數徽章、「標記審閱完成」前的確認數字，以及「複製給 Claude」的未解決數。對已標記審閱完成的文件新增「同意」，不會清除完成紀錄。
- **「📋 複製給 Claude」帶分類**：每則都標出分類名稱；開頭附上這次用到的分類各自該怎麼處理（只用到「見說明」時省略這段）；「同意」另列一段且不編號；意見空白時省略「→」那一行。原有的「原文已修改」等狀態註記照舊保留。

### 註解檔的保護

- **陌生欄位保留**：目前前端用固定的欄位清單寫回每則註解，較新版本加的欄位會在舊版存檔時被丟掉（0.6.0 就會把 `kind` 丟掉）。這次改成以記憶體裡的註解物件為底、再蓋上已知欄位，所以讀進來時就有、但這個版本不認得的欄位，存檔時會原樣寫回。同時立一條規則：程式算出來的暫存值一律不得掛在註解物件上。
- **不可信的輸入**：註解檔可能被手動改過或來自其他版本，所以檔案裡的 `kind`、`color` 原值一律先解析成八類之一，才拿來決定畫面上的樣式、名稱與提示；原值只用來存檔。

### 順帶調整的介面文字

- 加註框的存檔按鈕從「加註」改名為「儲存」，避免出現「按 [加註] → 寫意見 → 再按 [加註]」的重複。
- 卡片上刪除註解的按鈕從「刪除」改名為「刪除註解」，避免跟「刪除這些字」分類混淆。
- 切換介面語言後，滑鼠移到螢光上的提示也會跟著換成新語言。

## Capabilities

### New Capabilities

- `selection-actions`：選取文章文字後出現的小工具列與加註框的開關規則。預計的需求：
  - `Selection toolbar for article text`：何時出現、出現在哪裡、何時不出現（加註框或流程圖放大檢視開著時）。
  - `Copy selected text`：只放純文字、成功提示與工具列留著、兩段退路、朗讀結果。
  - `Annotate from the toolbar`：[加註] 打開加註框，位置當下重算並夾在視窗內。
  - `Toolbar dismissal`：點別處、Esc、選取被取消或改變、開檔或重新載入、打開流程圖放大檢視、視窗大小改變時收起。
  - `Keyboard operation`：焦點不自動移動、Tab 進入、方向鍵切換、Tab 離開、Esc 收起、工具列角色與名稱。
  - `Open annotation box is not interrupted`：加註框開著時不出現工具列、不清空草稿。
  - `Annotation box closes when another document opens`：開啟或重新載入文件時先關閉加註框，草稿不寫入新文件。
- `annotation-kinds`：八種註解分類與相關行為。名稱沿用原本規劃的 `annotation-kinds`：存檔的欄位就叫 `kind`，這個 capability 管的是「註解分類」這件事本身，分類的內容換了，但範圍沒變。預計的需求：
  - `Fixed set of annotation kinds`：八類的值、順序、名稱、處理方式、符號、顏色（淺色與深色模式）。
  - `Kind stored per annotation`：新註解一律寫 `kind`、不寫 `color`；`comment` 一律是字串。
  - `Missing or unknown kind is See comment`：沒有 `kind`、不認得的值、不是字串的值，一律當「見說明」顯示與處理，原值存檔時照寫回。
  - `Kind picker in the annotation box`：原生單選選項、兩欄排列、「見說明」第一格且預設、只有「見說明」必須寫意見。
  - `Kind is recognizable without color`：螢光開頭的符號色章、卡片分類名稱、滑鼠提示；色覺模擬下任兩類都分得出來。
  - `Kind can be changed on the card`：卡片小選單只改分類，不影響意見與審閱完成紀錄。
  - `Copy for Claude carries kinds`：每則帶分類、分類說明段、「同意」另列、意見空白省略箭頭。
  - `Agree annotations are not to-dos`：定義「未解決數」不含「同意」，左側徽章、標記完成前的確認、複製文字的摘要一律用這個定義。

### Modified Capabilities

- `sidecar-integrity`：修改需求 `Writes keep fields they do not manage`。原本是「註解只用一份欄位白名單送出」，改成「以記憶體裡的註解物件為底、蓋上已知欄位」，讀進來時就有的陌生註解欄位存檔時原樣保留；並明定暫存值不得掛在註解物件上。
- `review-status`：修改三條需求。
  - `Review-complete record stored in the sidecar`：需求裡的狀態圖寫著「新增註解」會讓已完成的文件回到未審閱，改成「新增待辦註解」，新增「同意」不改變狀態。
  - `Marking is guarded`：標記完成前確認的「未解決數」不含「同意」。
  - `Record follows the review workflow`：對已完成的文件新增「同意」，不清除完成紀錄。
- `back-to-top`：修改需求 `Back-to-top button in the reading pane` 的最後一個情境。原本寫「選取文字時按回到頂端，不會打開加註框」；選取後不再直接打開加註框，所以改成「不會出現選取工具列」，讓這個情境繼續有檢查意義。

以下規格維持原樣：
- `annotation-revision-diff`：「複製給 Claude」的原文狀態註記需求不變。分類名稱放在行號後面、引文前面，每則第一行仍以原文狀態註記結尾。
- `ui-i18n`：新字串照既有需求放進 en 與 zh-Hant 兩份語系檔、key 一致即可。切換語言後螢光提示跟著換，屬於既有需求「介面以目前語言顯示」的範圍。
- `favorites`：收藏列表沿用「未解決數徽章」，數字怎麼算由 `annotation-kinds` 定義。

## Impact

- **前端**
  - `reviewer.js`：選取處理（`#doc` 的 mouseup）改成先出工具列；新增工具列的顯示、定位、複製、收起與鍵盤處理；`openPopover` 改成依當下位置計算並夾在視窗內；`renderSwatch` 換成分類選項；`saveAnnotation` 改寫 `kind`、依分類決定意見可否留空、「同意」不清除完成紀錄；`wrapQuote`、`applyHighlights`、`renderSide`（分類色章與小選單、按鈕改名）、「📋 複製給 Claude」、`buildSidecar`、`#btnDone` 的未解決數都要跟著改；`loadFile` 一開始先關閉加註框與工具列；`applyLocale` 之後重跑 `applyHighlights`；移除 `COLORS`／`COLORHEX`。
  - `reviewer.html`：新增工具列與朗讀區；加註框的顏色圓點區改成分類選項區。
  - `reviewer.css`：八類的螢光、圓點與符號色章（淺色、深色兩組）；`mark.anno` 的基本底色；工具列與分類選項的樣式；`#doc` 加 `position: relative`；移除舊的四色螢光規則。
- **共用模組** `reviewer-diff.js`：新增分類清單、`kindOf`（解析分類）、`isTodo`（是否算待辦）、建立新註解與存檔合併的函式。前端與伺服器共用同一份。
- **伺服器** `server.cjs`：左側清單徽章用的 `annCounts` 改用 `isTodo` 計算。`/api/save` 與 `writeSidecar` 不需要改。
- **命令列** `bin/md-reviewer.js`：`--hook` 印出的 CLAUDE.md 建議指示目前寫「處理 status 為 open 的註解」，改成「依 `kind` 處理 status 為 open 的註解」。
- **多語系** `locales/en.json`、`locales/zh-Hant.json`：工具列按鈕、已複製、請按 Ctrl+C（含 macOS 版）、工具列的無障礙名稱與朗讀文字；八類的名稱、給審閱者的短提示、正式處理方式；加註框的「預設」標籤、分類群組名稱、可留空時的輸入框提示；複製文字的分類說明標題與「同意」段標題；「儲存」「刪除註解」兩個改名；歡迎畫面 `doc.empty` 的操作說明改成「選取 → [複製]／[加註]」。兩份 key 必須一致。
- **註解檔格式**：每則註解新增選填欄位 `kind`；`comment` 一律是字串。`schema`（註解檔頂層用來標示格式版本的數字）維持 `1`，舊檔不需要轉換。
- **文件與版本**
  - `README.md`、`README.zh-Hant.md`：「怎麼用」的操作步驟；新增「註解分類」一節（八類與處理方式）；註解檔格式說明（`kind`、`color` 只出現在舊註解、`comment` 可能是空字串）；給 AI 的觸發指示改成「依 `kind` 處理」；跨設備一節補上「每台設備都要用 0.7.0 以上」，並寫明「意見空白的註解在舊版存檔後，分類會被丟掉，變成沒有內容的註解」。
  - `CHANGELOG.md`：新增 0.7.0 條目，包含上面那句相容性提醒。
  - `package.json`：版本升到 **0.7.0**。這是 minor 版本（版本號中間那一位，代表新增功能、而且與舊版相容）。
- **測試**：`test/diff.test.cjs` 加入分類相關檢查：沒有分類與不認得的分類都解析成「見說明」、「同意」不算待辦、舊註解存檔後內容不變、陌生欄位保留、新註解不寫 `color`。瀏覽器端的行為（選取、複製、分類、鍵盤、色覺模擬）以手動實測驗證，使用 `DEMO.md` 與 `DEMO.review.json` 的複本，不動原檔。
- **相容性**：0.6.0 以前的版本開啟 0.7.0 的註解檔時看不到分類，新註解顯示成瀏覽器預設的黃色螢光；在舊版存檔會丟掉所有 `kind`。意見空白的註解（例如只標了「刪除這些字」）因此會變成沒有內容的註解。README、CHANGELOG 與回退說明都要寫清楚。
- **需同步更新的外部文件**：claude-config repo 的 `skills/md-reviewer/SKILL.md`（不在本 repo）。第 2 節「讀回審閱」要改成依 `kind` 處理，處理文字照抄語系檔的英文版正式文字；沒有 `kind` 的舊註解當「見說明」；「同意」不必處理。這份 PR 在 0.7.0 發布前就準備好，發布後立即合併。

## Non-goals

- 在卡片上修改意見文字（這次只開放改分類）。
- 右側註解欄依分類篩選或分組。
- 使用者自訂分類、符號或顏色。
- 把舊註解的 `color` 換算成某個分類，或改寫舊的註解檔。
- 只用鍵盤選取文字（瀏覽器的「插入點瀏覽」模式）時出現工具列；工具列只在放開滑鼠時判斷。
- 觸控裝置專用的選取操作。
- [複製] 連同格式（HTML）一起複製。
- 工具列加入 [複製]、[加註] 以外的按鈕。
